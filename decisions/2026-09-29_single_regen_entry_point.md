# Decision Gate - 2026-09-29

## Decision

Make `scripts/ingest.sh` the single complete regeneration path for every derived
file: chain `scripts/block_overview.py` after the existing `scripts/status_digest.py`
call, so both `bash scripts/ingest.sh` (import) and `bash scripts/ingest.sh --sync-only`
(after a plan week-file edit) leave `README.md`, `STATUS.md`, and
`plans/2026-half-marathon/BLOCK_OVERVIEW.md` current. Add `tests/test_block_overview.py`,
and record the source-to-generated-view field mapping in
`plans/2026-half-marathon/README.md`.

Explicitly **rejected**: packaging the import routine as a Claude skill, a slash
command, or a new `regen.sh` wrapper — the shape proposed by the action item in
`retros/weekly/week_2026-09-28_work_session.md`.

## Facts

- `scripts/block_overview.py` was an orphan. Nothing called it — not `ingest.sh`,
  not `ingest_coros_fit.py`, not any test. It was documented as a manual
  "rebuild with ..." step in `plans/2026-half-marathon/README.md` and nowhere else.
- Wiring before this change:

  | Derived file | Generated by | Automated? |
  | --- | --- | --- |
  | `README.md` current-week block | `ingest_coros_fit.py` (`--sync-only` too) | yes, via `ingest.sh` |
  | `STATUS.md` | `status_digest.py` | yes, chained in `ingest.sh` |
  | `plans/2026-half-marathon/BLOCK_OVERVIEW.md` | `block_overview.py` | no — manual only |

- The 2026-09-28 work session lost three round trips. Two causes, both knowledge
  gaps rather than tool gaps: the plan file's **Run** cell (not its Notes cell,
  and not the weekly log's `- Planned:` line) is what feeds the README's Planned
  column; and a plan edit was followed by `block_overview.py` + `status_digest.py`
  but not `ingest.sh --sync-only`, leaving the README stale until the user asked
  why.
- `block_overview.py` was the only generator in the repo with no test.
- A skill body covering the import routine would have restated
  `docs/import_runbook.md` (~1,700 tokens) without reducing load-time cost, and
  would have added a permanent passive cost: its description sits in every
  session's skill list whether or not an import happens.

## Preference

Enforcement over prose. A step that must be remembered is a step that will be
forgotten; wiring it into the script that already runs removes the class of
error rather than documenting it. This is the same principle as the operator
boundary — the only manual step in this repo is dropping `.fit` files.

Single entry point over a menu of generators. Three scripts a caller must know
to run in the right combination is the actual defect; one command that always
leaves the repo consistent is the fix.

## Risk

- `block_overview.py` now runs on every import, so its failure aborts the ingest
  under `set -euo pipefail`. Accepted deliberately, not swallowed: its only error
  is `SystemExit("No week files found")`, which means the plan week files are
  gone — real corruption, not an in-progress edit. `status_digest.py` already
  draws the line in the same place, and it is the reverse failure (silent
  staleness) that cost the session being retro'd.
- Promoting an untested script onto the critical path of every import is the
  material risk. Mitigated by `tests/test_block_overview.py` landing in the same
  change, covering normal render, idempotence (two runs produce identical bytes),
  and the no-week-files `SystemExit`.
- Every import commit now also touches `BLOCK_OVERVIEW.md` when the block grid
  changes. Larger diffs, but they are generated content and the file already
  carries a do-not-edit-by-hand banner.
- Rejecting the skill leaves the routine discoverable only through
  `docs/import_runbook.md` and `AGENTS.md`. Acceptable: `AGENTS.md` is auto-loaded
  every session, which is a stronger guarantee than a skill description the model
  must choose to expand.

## Final Call

Proceed. The retro's action item named a skill, but the failure it came from was
a missing wiring edge plus a missing field-mapping fact — neither of which a
skill fixes. One line in `ingest.sh` closes the wiring gap permanently, a test
makes the promotion safe, and the field mapping goes in the file that gets read
when someone edits a plan. Do not revisit the skill packaging without new
evidence that load-time cost, not wiring, is the bottleneck.
